- **遇到的坑**（**重要，都是实测才发现的**）：
  - **`p_update` 策略允许自我提权**：`using (id = auth.uid())` 只限行不限列，普通用户 `PATCH /profiles?id=eq.<自己> {"role":"admin"}` 就能变管理员，先审后发直接失效。已加 `guard_profile_role` 触发器
  - **guard 第一版写错了**：条件里 `not is_admin()` 在服务端上下文（`auth.uid()` 为 null）恒为真，导致**连 SQL Editor 都设不了管理员**——`update profiles set role='admin'` 静默回滚。改成 `auth.uid() is not null and not is_admin()` 才对
  - **`create function` 默认 `grant execute to public`**：不 revoke 的话未登录可 `POST /rest/v1/rpc/get_dataset_snapshot` 拉全量数据。9 个函数全部显式 `revoke from public, anon` 再 `grant to authenticated`
  - **revoke `is_admin` from anon 会误伤读表**：策略表达式里调用 `is_admin()`，anon 无执行权时未登录读 `balls` 报 `42501 permission denied for function is_admin` 而不是空数组。只能给 anon 放行（函数恒 false，不泄露数据）
  - **`bump_dataset_version` 必须 security definer**：`dataset_meta` 有 RLS 无写策略，普通函数在管理员绕过 RPC 直接 `PATCH /balls` 时会因更新 `dataset_meta` 被拒而使整条 update 失败
  - `revoke execute ... from public, anon` 后 advisors 仍会报 `authenticated_security_definer_function_executable` 9 条——这是 D12 的必然结果，**不要试图清零**
- **遗留问题**：
  - 数据库密码仍未拿到（T0.5 备份前必须去 Dashboard 重置）
  - 表里还没有业务数据，`balls`/`advanced`/`comments` 全 0
