### 2.3 为什么暗色主色不是 `#F06632`

1. **对比度**：`#F06632` 在 `#1C1C1F` 上只有 5.4:1，12–13px 的次级信息会发闷；`#FF7A45` 是 6.6:1。
2. **和危险色撞车**：`#DB3340` 本身偏橘红，深底上和 `#F06632` 都是一团红，区分不出主色与警示。
3. **观感**：高饱和橘红大面积铺深底会"发颤"，提亮 6–8% 后更稳。

色相保持一致（约 16°），只调亮度与饱和度，品牌延续性不丢。

### 2.4 按钮文字

白字放在 `#FF7A45` 上对比度只有 2.6:1，不达标。处理方式：

- **实心按钮底色用 `--primary-active`**（亮 `#D9531F` / 暗 `#E8622C`），白字约 3.4:1，配 15px / 600 字重符合 WCAG 大字标准
- hover 时才切到 `--primary`（`#FF7A45`）

### 2.5 暗色下的图片（容易漏的坑）

路线图、击球点图是**白底或透明底 PNG**，直接放暗色卡片上非常刺眼。

旧 WPF 代码里已经用 `PrimaryBrush` 给图片容器加了底色——说明原作者踩过这个坑。新 UI 必须保留：

```css
.image-frame {
  background: #FFFFFF;   /* 两种主题下都保持白色 */
  border-radius: 10px;
  padding: 8px;
}
```

## 3. 主题实现

### 3.1 CSS 变量

```css
:root {
  --bg: #EEEEEE;
  --surface: #FFFFFF;
  --primary: #F06632;
  --primary-active: #D9531F;
  /* …其余见第 2 节 */
}
html.dark {
  --bg: #131315;
  --surface: #1C1C1F;
  --primary: #FF7A45;
  --primary-active: #E8622C;
}
```

### 3.2 Element Plus 主色覆盖

Element Plus 2.x 用 CSS 变量控制主色，直接覆盖即可：

```css
:root {
  --el-color-primary: var(--primary);
  --el-color-primary-light-3: color-mix(in srgb, var(--primary) 70%, #fff);
  --el-color-primary-dark-2: var(--primary-active);
}
```

暗色模式引入 `element-plus/theme-chalk/dark/css-vars.css`，并在 `<html>` 上加 `dark` class。

### 3.3 跟随系统

三档设置，默认 `system`：

```ts
type ThemeMode = 'system' | 'light' | 'dark'
```

```ts
const mq = window.matchMedia('(prefers-color-scheme: dark)')

function apply(mode: ThemeMode) {
  const dark = mode === 'dark' || (mode === 'system' && mq.matches)
  document.documentElement.classList.toggle('dark', dark)
}

mq.addEventListener('change', () => apply(currentMode))
```

### 3.4 Electron 侧同步

渲染进程切 class 只影响页面内容；窗口边框、滚动条、原生右键菜单要主进程配合：

```ts
// main
ipcMain.on('theme:set', (_, mode: 'system' | 'light' | 'dark') => {
  nativeTheme.themeSource = mode
})
```

`nativeTheme.themeSource = 'system'` 时窗口装饰自动跟随系统，与渲染进程的 class 保持一致。

### 3.5 实际实现（T1.2，以此为准）

| 位置 | 内容 |
|---|---|
| `src/renderer/src/styles/theme.css` | 两套变量（第 2 节全量）+ 圆角/阴影/字号 token + Element Plus 变量映射 + `.image-frame` |
| `src/shared/types/theme.ts` | `ThemeMode` / `ThemeState` / `ThemeApi`，主进程与渲染进程共用 |
| `src/main/theme.ts` | 持久化 `<userData>/theme.json`（写 `.tmp` → 原子 rename）、设置 `nativeTheme.themeSource`、`theme:get` / `theme:set` |
| `src/renderer/src/theme/index.ts` | `initTheme()` / `setThemeMode()`，负责 `html.dark` 上色与 `matchMedia` 监听 |

两条关键约定：

1. **持久化放主进程**，不用 `localStorage`。窗口创建前就要确定主题（`initTheme()` 在 `whenReady` 里、`createWindow()` 之前），否则首帧必闪。渲染进程首帧按 `prefers-color-scheme` 上色，异步拿到的 `mode` 只用于按钮选中态。
2. **只保留一条上色路径**。改 `nativeTheme.themeSource` 会让 Chromium 的 `prefers-color-scheme` 跟着变，`matchMedia` 的 change 事件自动触发上色；再额外监听 IPC 推送会造成两条路径竞争、出现中间态。

## 5. 功能清单（重写时逐项打勾）

左侧是旧版功能点，右侧是新实现方式。**这是防止漏功能的核对表。**

### 5.1 窗口外壳

| 旧版 | 新版 |
|---|---|
| 无边框窗口（`ShowNonClientArea=False`） | `frame: false` |
| 自定义关闭/最小化按钮 | IPC → `win.close()` / `win.minimize()` |
| 窗口拖拽移动 | `-webkit-app-region: drag`（按钮区 `no-drag`） |
| 单实例运行（Mutex） | `app.requestSingleInstanceLock()` |
| 固定 1402×902 不可缩放 | **最小 1024×700，可缩放** |
| 全局异常 + log4net | `electron-log` + `uncaughtException` |

**实现位置（T1.3 已完成）**：`src/main/window.ts`（窗口创建 + `window:*` IPC）、`src/renderer/src/components/TitleBar.vue`（自绘标题栏）、`src/shared/types/window.ts`（`WindowControls` 接口）。

两个坑：

- **双击最大化交给原生**。`-webkit-app-region: drag` 区域的双击由 Windows 在非客户区处理（`WM_NCLBUTTONDBLCLK`），**不要自己绑 `dblclick`**，否则会切换两次、看起来像没反应。副作用：CDP 合成的鼠标事件到不了那一层，这条只能人工验证。
- **无边框 ≠ 无边框像素**。保留缩放能力就会保留 `WS_THICKFRAME`，`outerWidth - innerWidth` 约 16px 是正常的；判断有没有原生标题栏看**垂直差值**（有标题栏时约 30px，无边框时只有个位数）。

#### 布局形态：全部是悬浮卡片（2026-10-29 修订）

页面底色 `--bg`（浅灰 / 近黑），**侧栏、顶部栏、内容区都是独立的白卡片**，四边留 `0.75rem` 间距、`--radius-lg` 圆角、`--shadow-card` 很淡的阴影。统一用 `.card` 工具类（`theme.css`），以后的列表卡片也走这个类。

阴影刻意做得很淡：`0 1px 2px rgb(0 0 0 / 4%), 0 4px 12px rgb(0 0 0 / 4%)`。立体感靠「灰底 + 白卡 + 1px 边框」撑，不靠重阴影。

#### 侧栏结构：LOGO 固定 + 菜单区独立滚动

```
.sidebar（flex column，overflow: hidden —— 卡片本身不滚）
├─ .sidebar__logo   固定，不随菜单滚动；内容水平居中；padding: 2rem 0.875rem 1.5rem
└─ .sidebar__nav    flex: 1 + overflow-y: auto —— 唯一的滚动容器
                    padding: 0 1rem 1.25rem（底部留出与卡片下边的间距）
```

- LOGO 区：图标 + 文字整体水平居中（`justify-content: center`），文字 `font-weight: 600`（只有 Regular，这里是**刻意要的合成加粗**）
- 滚动条：`width: 4px`、`thumb` 用 `--text-3`、`border-radius: 2px`，**只覆盖菜单区**，不压 LOGO 区、不压卡片底边
- 折叠态：LOGO 只留圆形图标（同样居中）；菜单区 `padding-inline: 0.5rem`

#### 一级菜单：左侧竖线表示选中

- **不用箭头图标**（原来靠 chevron 旋转表示展开）
- 每个一级菜单前有图标（`<AppIcon :name="group.icon" />`，`1.25rem`，默认 `--text-3` 灰），图标与文本间距 `0.875rem`
- 一级菜单文字：`1.0625rem` / `400`（**不加粗**，见下方字体说明）
- 当前分组：菜单最左侧出现一条 **3px × 18px 的主题色竖线**（`--sidebar-indicator`），距卡片左边缘约 `15px`（`left: 0`，靠侧栏内边距留出呼吸感），**图标与文本颜色都不变**
- 折叠态：**不显示竖线**（68px 宽没有它的位置），改成**激活分组的图标显示主题色**，其余图标保持 `--text-3`；`title` / `aria-label` 仍是分组名

#### 一级菜单展开/收起：弹簧动画

```css
.group__panel {
  display: grid;
  grid-template-rows: 0fr;              /* 收起 */
  transition: grid-template-rows 320ms cubic-bezier(0.34, 1.56, 0.64, 1);
}
.group__panel.is-open { grid-template-rows: 1fr; }
.group__items { overflow: hidden; min-height: 0; }
```

**关键点：`grid-template-rows` 的过冲会被吃掉**。实测高度曲线是 0 → 208 单调上升、峰值正好 208，`cubic-bezier` 的 1.56 过冲在 `1fr` 处被截断，所以光靠它做不出「弹簧」。

真正的回弹放在**条目自身**：

```css
.item {
  opacity: 0;
  transform: translateY(-0.875rem);
  transition:
    transform 340ms cubic-bezier(0.34, 1.8, 0.5, 1),
    opacity 200ms ease;
}
.group__panel.is-open .item { opacity: 1; transform: translateY(0); }
```

实测 `translateY` 曲线：`-14 → 0 → +2.5 → 0`（过冲 2.5px 后回落），配合高度平滑展开，收放时有轻微弹一下的感觉。

> 用 `v-show` 做不到：它直接切 `display`，没有中间态。要动画就必须让元素一直在 DOM 里，靠 `grid-template-rows` / `height` 控制可见高度。

#### 二级菜单：两端对齐

文字 `1rem` / `400`，颜色 `--text-1`（与一级菜单同色，层级靠字号区分）。

对齐方式（照用户给的参考图）：**同一组内按最长标签算统一宽度，文字两端对齐**。
两个字（`黄球`）会把多出来的宽度摊到**字与字之间**，撑满到三个字（`咖啡球`）的宽度 —— 左右边界都对齐，视觉上也是居中的。

```css
.item__label {
  display: inline-block;
  text-align: justify;
  text-align-last: justify;
  white-space: nowrap;
}
```

- 宽度用 **canvas `measureText`** 量（`document.fonts.ready` 之后，避免量到回退字体），结果写到 `.item__label` 的行内 `width`
- **不要往数据里插空格**：`&nbsp;` / 全角空格会随字体变化对不齐，而且污染数据
- 选中项 = 浅橘底（`--sidebar-active-bg`，`color-mix(primary 10%, surface)`）+ 橘色文字

#### 字体：只有 Regular，避免用 600/700

`PingFangSC-Regular.ttf` 只有 400 一个字重。**界面里不要写 `font-weight: 600/700`**——浏览器会做合成加粗，中文字形会发虚、笔画糊在一起。需要层级时用**字号 + 颜色**，不要用字重。

以后如果确实需要真加粗，补一个 `PingFangSC-Semibold.ttf` 并在 `theme.css` 的 `@font-face` 里加 `font-weight: 600` 的声明。

## 6. 布局与尺寸

**仅 PC，不做移动断点。** 但**禁止写死像素尺寸**——目的是窗口缩放不破版。

| 约束 | 值 |
|---|---|
| 最小窗口 | 1024 × 700 |
| 侧栏宽度 | 240px（折叠 64px） |
| 顶部栏高度 | 64px |
| 内容区内边距 | 16–24px |
| 卡片网格 | `grid-template-columns: repeat(auto-fill, minmax(320px, 1fr))` |
| 卡片最大宽度 | 720px（单列时居中） |

写法约束：
- 字号用 `clamp()`，不写死 px
- 所有容器 `max-width: 100%`
- 长文本 `white-space: pre-wrap` + `overflow-wrap: anywhere`（走位说明可能很长）

## 7. WPF → Web 的交互差异

| 场景 | 坑 | 处理 |
|---|---|---|
| 图片选择 | `el-upload` 默认选完就上传 | `:auto-upload="false"` |
| 窗口拖拽 | 整条顶栏设 `drag` 后按钮点不动 | 按钮/下拉/输入框加 `-webkit-app-region: no-drag` |
| 中文输入法 | 拼音中途触发搜索 | 监听 `compositionstart/end`，组合期间不筛选 |
| 右键菜单 | Web 无默认菜单 | 自定义或禁用 |
| 滚动 | 别套自定义 ScrollViewer | 用原生滚动 |
| 关闭窗口 | 有未保存表单时直接关 | `win.on('close')` 拦截确认 |
| 长文本 | 走位说明可能几百字 | `pre-wrap` + 卡片自适应高度 |
