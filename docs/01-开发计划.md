**为什么这样写**（实测依据）：
- 保活打 `/auth/v1/health` 而不是 `/rest/v1/`：后者根路径只接受 secret key，publishable key 会 401；`/auth/v1/health` 带 apikey 返回 200。**不带 apikey 是 401，所以 header 不能省**
- 备份用 **Session pooler** 连接串而不是 `db.<ref>.supabase.co`：实测直连域名在本机 DNS 解析失败（只有 IPv6），GitHub runner 也不支持 IPv6
- **`pg_dump` 必须用绝对路径**：首次跑失败 `server version mismatch (17.11 vs 16.15)`。原因不是没装 `postgresql-client-17`，而是 runner 上 `/usr/bin/pg_dump` 直接指向 16 的二进制，装 17 也不会改指向。改为 `$PGBIN/pg_dump`（`/usr/lib/postgresql/17/bin`）+ 断言该文件存在

### 一条新增纪律（已写入 AGENTS.md 铁律）

**所有 DDL 必须落成 migration 文件并提交 git。** MCP 只是执行通道，不是真相来源。

原因：如果某次会话直接用 `execute_sql` 改了表结构，数据库和 git 就不一致了——下一个会话读 `supabase/migrations/` 会以为 schema 还是旧的。**后果是灾难性的**，因为没人知道线上表结构到底是什么。

规则：

- DDL（建表、改列、加索引、改策略、加函数）→ 必须先写文件，再 `apply_migration`
- `execute_sql` 只用于查询和临时验证，**禁止用来改结构**
- 每次 DDL 之后跑一次 `get_advisors(type='security')`

2. **CDP 的网络模拟属于会话级**：`emulateNetworkConditions` / `setBlockedURLs` 在 ws 断开时立刻复位。"断网 → 检查 DOM"必须写在**同一个脚本**里，分两次跑第二次读到的就是 `onLine=true`。

5. **按钮禁用之外还要挡一次**：表单 `save()` 里补了 `offline` 判断 —— 回车提交不经过 `disabled`。
6. **`.env.local` 里的 dev 自动登录账号失效**（`邮箱或密码不对`，`auth.status=signedOut`）。UI 验证用**内存里临时伪造**的 auth 状态（`profile.role=admin`）把写按钮渲染出来，刷新后即还原，**没碰数据库**。

- 写操作的兜底仍靠各 api 的 `translate*Error`（断网时给「连不上服务器，检查一下网络」）；没在 RPC 层统一拦截 —— 读操作也走 RPC，全拦会让"离线浏览时点重试"变成假错误。
- 评论 / 通知这类"读也要联网"的区块，离线时仍显示各自的加载失败文案（它们不读快照），属预期。
- 通知**单条点击**仍会尝试标已读（失败静默、不挡跳转），只有「全部已读 / 清空已读」被禁用 —— 标已读是低风险写，不该因为它拦住看通知。

**坑**：

1. **资源加载失败必须用捕获阶段**：`img` / `script` / `link` 的 `error` 事件**不冒泡**，`window.addEventListener('error', fn)` 收不到；要传第三个参数 `true`，并且用 `event.target instanceof HTMLElement` 区分"资源失败"和"脚本抛错"（后者 `message` 非空）。
2. **IPC 传不了 `Error` 实例**：结构化克隆会丢掉 `message` / `stack`，必须在渲染层序列化成字符串再发，否则主进程只能写出一句 `{}`。
3. **`electron-log` 的 scope 默认补白**：`main` 与 `renderer:resource` 长度不同会让正文起始列来回跳；`log.scope.labelPadding = false` 关掉（类型定义里没有这个字段，要断言）。
4. **`uncaughtException` 里不要弹对话框**：electron-log 自带的 `errorHandler` 会弹框并建议重启，本项目改成只记日志继续跑 —— 内部教学工具，不该因为一条渲染异常把人踢出去。
5. **复制路径依赖窗口焦点**：`navigator.clipboard.writeText` 在窗口未聚焦时抛 `NotAllowedError`（CDP 里第一次测就是这个原因）。提示文案写的是"手动选中"，所以路径文本加了 `user-select: text`。

- 日志没有"上报"能力（无 Sentry / 无远端收集），靠用户把 `main.log` 发过来 —— 内部圈子可接受，也符合 ¥0 约束。
- `main.old.log` 只保留一代（electron-log 默认），要看更早的得自己留档。
- 渲染层日志只覆盖异常与同步失败，**没有记录业务写操作**（评论 / 审核 / 回收站）—— 这些在服务端 `admin_actions` 里有审计，不重复记。
- 日志级别没有做成设置项（生产固定 info），需要更详细时得改代码重启。

## 任务做不完怎么办（很常见）

不要硬做，也不要留半成品。二选一：

1. **回退**：`git checkout -- .`，任务状态改回 `TODO`，在日志写清"为什么没做完"
2. **拆任务**：`T3.2` 拆成 `T3.2a 只做筛选`、`T3.2b 只做卡片`，前者 `DONE`，后者 `TODO`

**绝对不要提交编译不过的代码**——下一个会话会以为它是好的。
