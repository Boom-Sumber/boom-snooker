**为什么这样写**（实测依据）：
- 保活打 `/auth/v1/health` 而不是 `/rest/v1/`：后者根路径只接受 secret key，publishable key 会 401；`/auth/v1/health` 带 apikey 返回 200。**不带 apikey 是 401，所以 header 不能省**
- 备份用 **Session pooler** 连接串而不是 `db.<ref>.supabase.co`：实测直连域名在本机 DNS 解析失败（只有 IPv6），GitHub runner 也不支持 IPv6
- **`pg_dump` 必须用绝对路径**：首次跑失败 `server version mismatch (17.11 vs 16.15)`。原因不是没装 `postgresql-client-17`，而是 runner 上 `/usr/bin/pg_dump` 直接指向 16 的二进制，装 17 也不会改指向。改为 `$PGBIN/pg_dump`（`/usr/lib/postgresql/17/bin`）+ 断言该文件存在

### 一条新增纪律（已写入 AGENTS.md 铁律）

**所有 DDL 必须落成 migration 文件并提交 git。** MCP 只是执行通道，不是真相来源。

原因：如果某次会话直接用 `execute_sql` 改了表结构，数据库和 git 就不一致了——下一个会话读 `supabase/migrations/` 会以为 schema 还是旧的。**后果是灾难性的**，因为没人知道线上表结构到底是什么。

规则：

- DDL（建表、改列、加索引、改策略、加函数）→ 必须先写文件，再 `apply_migration`
- `execute_sql` 只用于查询和临时验证，**禁止用来改结构**
- 每次 DDL 之后跑一次 `get_advisors(type='security')`

| `get_advisors(security)` | 无新增项（仍是已知的 6 条 anon / 16 条 authenticated security definer 函数告警） |

**坑**：

1. **canvas 画完是位图，主题切换不会自己变**：第一次截图亮色主题下验证码是一块深色底 —— 因为对话框是在暗色下打开的，`html.dark` 变了画布内容不变。修法：`MutationObserver` 监听 `documentElement` 的 class，**重绘同一张码**（不换字符，否则用户刚看清就变了）。
2. **`el-form-item input` 会把单选框也选进来**：性别是 `el-radio`，里面也有 `<input type="radio">`，按下标填表单会错位。改用 `.el-input__inner`（只命中 `el-input`）。
3. **昵称约束要放在数据库**：`profiles_nickname_check`（1~24 字）挡住空串和超长昵称，前端 maxlength 只是体验，绕过 UI 直接打 PostgREST 也能拦住。
4. **注册即登录依赖"关闭邮箱确认"**：如果哪天后台把确认打开，`signUp` 拿不到 session，代码会返回「注册成功，但需要先确认邮箱才能登录」—— 别把这段当死代码删掉。

**测试数据清理**：测试账号 `t37-…@snooker.local` 已从 `auth.users` 物理删除（级联清 profiles），用户数回到 **3 / 3**；`dataset_version` 未变。

**遗留问题**：

- **Supabase 的「Leaked Password Protection」是关的**（advisor 提示），开它要手动去 Dashboard → Auth → Password security 勾选；免费可用，建议开
- 昵称**没有唯一约束**，两个人都能叫同一个名字（旧版也没有）；要唯一得加 `unique` + 前端提示
- 注册没有邮箱验证（D13 有意为之），理论上可以用不存在的邮箱注册；内部圈子可接受
- 头像只有两张内置图，用户不能上传自己的

**为什么校验写在 el-form 的 validator 里**：单独挂 `@blur` 会与「点注册」产生竞态 —— 表单可能先通过校验、异步请求后到。放进 validator 后 `validate()` 会等它完成，状态只有一个来源。

**实测（CDP 驱动真实 DOM）**：

| 场景 | 结果 |
|---|---|
| 未登录点顶栏头像 | 登录框打开，底部按钮文案「使用邀请码注册」 |

| 走 store 真实注册（错码） | `Database error saving new user` → 经 `explainSignUpFailure` 还原成「邀请码不存在…」 |

**坑**：

1. **supabase-js 和 REST 的错误文案不一样**（见 T2.6 坑 1）：REST 能拿到 token，supabase-js 只给 `Database error saving new user`。所以「错码提示」必须靠提交后再预校验一次，光靠 `translateAuthError` 映射 token 是无效代码
2. **必填星号要显式写 `required: true`**：只写 `validator` 的话 el-form 不会加 `is-required`，视觉上「邀请码」看起来不是必填
3. **dev 自动登录会挡住测试入口**：`dev/auto-login.ts` 让顶栏直接是已登录态，测注册框前要先 `signOut()`

1. **回退**：`git checkout -- .`，任务状态改回 `TODO`，在日志写清"为什么没做完"
