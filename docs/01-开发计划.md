**为什么这样写**（实测依据）：
- 保活打 `/auth/v1/health` 而不是 `/rest/v1/`：后者根路径只接受 secret key，publishable key 会 401；`/auth/v1/health` 带 apikey 返回 200。**不带 apikey 是 401，所以 header 不能省**
- 备份用 **Session pooler** 连接串而不是 `db.<ref>.supabase.co`：实测直连域名在本机 DNS 解析失败（只有 IPv6），GitHub runner 也不支持 IPv6
- **`pg_dump` 必须用绝对路径**：首次跑失败 `server version mismatch (17.11 vs 16.15)`。原因不是没装 `postgresql-client-17`，而是 runner 上 `/usr/bin/pg_dump` 直接指向 16 的二进制，装 17 也不会改指向。改为 `$PGBIN/pg_dump`（`/usr/lib/postgresql/17/bin`）+ 断言该文件存在

| admin | 新增可见记录是否 bump | **bump**（371→372） |
| admin | 能否看到待审队列 | 能看到 |
| admin | 直接把自己改成 superadmin | **403**（列级授权拦住） |
| superadmin | 新增记录 / 改记录 | **403** / **命中 0 行** |
| superadmin | 能否看到待审记录 | 能看到（只读） |

**三个必须记的坑**：

1. **服务端上下文会被当成普通用户**（`014` 修正）。`auth.uid()` 为 null 时 `has_any_role()` 恒 false，导致 SQL 里审核通过一条记录，`RETURNING` 仍是 `pending`。这跟 T0.2 的 `guard_profile_role` 是同一个错误，**第二次踩**。
2. **RLS 管不了列**（`013` 修）。`p_update` 只限制「哪一行」，管理员能 PATCH 自己的 `role` 变成 `superadmin` 直接提权。必须 `revoke update` + `grant update (nickname, avatar)` 做列级授权。
3. **策略里用到的函数必须给 anon EXECUTE**（`015`）。否则未登录读表报 `42501 permission denied for function ...` 而不是干净的空数组。

**advisors 现状**：`rls_disabled` 0 条；剩 3 条 anon + 13 条 authenticated 的 security definer 告警，全部是策略函数与业务 RPC，属已知可接受项。

**关键实现细节**：`upsert_ball` 必须在函数里**再查一次 `owner_id`**。RLS 的 `with check` 只校验写入后的行，`on conflict do update` 时旧行的归属不在校验范围——不显式查，管理员就能靠传 `id` 改别人的记录。

**四角色权限合计 42 项测试**（T0.7 17 项 + T0.8 25 项），测试数据全部清理：122 行记录、`version=1`、只剩 2 个正式账号。

**advisors**：`rls_disabled` 0 条；3 条 anon + 16 条 authenticated 的 security definer 告警（策略函数与业务 RPC，已知可接受）；1 条 Auth 的 Leaked Password Protection 未开启（Dashboard 手动，可选）。

### 一条新增纪律（已写入 AGENTS.md 铁律）

**所有 DDL 必须落成 migration 文件并提交 git。** MCP 只是执行通道，不是真相来源。

原因：如果某次会话直接用 `execute_sql` 改了表结构，数据库和 git 就不一致了——下一个会话读 `supabase/migrations/` 会以为 schema 还是旧的。**后果是灾难性的**，因为没人知道线上表结构到底是什么。

规则：

- DDL（建表、改列、加索引、改策略、加函数）→ 必须先写文件，再 `apply_migration`
- `execute_sql` 只用于查询和临时验证，**禁止用来改结构**
- 每次 DDL 之后跑一次 `get_advisors(type='security')`

## 任务做不完怎么办（很常见）

不要硬做，也不要留半成品。二选一：

1. **回退**：`git checkout -- .`，任务状态改回 `TODO`，在日志写清"为什么没做完"
2. **拆任务**：`T3.2` 拆成 `T3.2a 只做筛选`、`T3.2b 只做卡片`，前者 `DONE`，后者 `TODO`

**绝对不要提交编译不过的代码**——下一个会话会以为它是好的。
