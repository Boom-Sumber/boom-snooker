**为什么这样写**（实测依据）：
- 保活打 `/auth/v1/health` 而不是 `/rest/v1/`：后者根路径只接受 secret key，publishable key 会 401；`/auth/v1/health` 带 apikey 返回 200。**不带 apikey 是 401，所以 header 不能省**
- 备份用 **Session pooler** 连接串而不是 `db.<ref>.supabase.co`：实测直连域名在本机 DNS 解析失败（只有 IPv6），GitHub runner 也不支持 IPv6
- **`pg_dump` 必须用绝对路径**：首次跑失败 `server version mismatch (17.11 vs 16.15)`。原因不是没装 `postgresql-client-17`，而是 runner 上 `/usr/bin/pg_dump` 直接指向 16 的二进制，装 17 也不会改指向。改为 `$PGBIN/pg_dump`（`/usr/lib/postgresql/17/bin`）+ 断言该文件存在

### 一条新增纪律（已写入 AGENTS.md 铁律）

**所有 DDL 必须落成 migration 文件并提交 git。** MCP 只是执行通道，不是真相来源。

原因：如果某次会话直接用 `execute_sql` 改了表结构，数据库和 git 就不一致了——下一个会话读 `supabase/migrations/` 会以为 schema 还是旧的。**后果是灾难性的**，因为没人知道线上表结构到底是什么。

规则：

- DDL（建表、改列、加索引、改策略、加函数）→ 必须先写文件，再 `apply_migration`
- `execute_sql` 只用于查询和临时验证，**禁止用来改结构**
- 每次 DDL 之后跑一次 `get_advisors(type='security')`

### T3.4 修订 2（2026-10-31）：彩球拆详情页 / 图片去白底 / 返回按钮图标

**用户三条反馈**：

1. 详情页的图片卡片不要白色背景，改透明 —— 暗色主题下一大块白很突兀
2. 返回按钮的图标不协调 → 换成 Element Plus 的 `ArrowLeftBold`，并加大图标与文字的间距
3. 彩球列表页也照进阶的做法，拆成「索引页 + 详情页」

**改法**：

| 文件 | 改动 |
|---|---|
| `views/BallDetailView.vue`（新增） | 返回 → 标题（力度大字 + 进袋方式）→ 彩球/袋口/作者/时间 → 三张图（击球点/蓝点/路线，有哪张显示哪张，点开可左右翻）→ 方法 / 低杆走位 / 高杆走位 / 补充说明；本人记录可编辑 / 删除；底部留评论区位置 |
| `components/BallCard.vue` | 改成索引卡：预览图（击球点 → 蓝点 → 路线 依次兜底）+ 力度（1.375rem 主题色）+ 进袋方式 + 作者/日期；整卡可点（`role="link"` + `tabindex="0"`），`···` 用 `@click.stop` |
| `views/BallView.vue` | 卡片 `@open` → `/balls/<color>/<id>`；网格 `minmax(20rem)` → `minmax(15rem)`；**筛选条件写进 URL query**（见坑 1） |
| `views/AdvancedDetailView.vue` | 图片容器 `background: transparent`、去掉边框与内边距（空图时用虚线框）；返回按钮换 `ArrowLeftBold` + `gap: 0.5rem` |
| `components/AdvancedCard.vue` | 预览图容器同样去掉白底 |
| `package.json` | 显式声明 `@element-plus/icons-vue@^2.3.2`（原来只是 node_modules 里存在，没写进依赖，直接 import 是"侥幸能用"） |

**实测（CDP + 暗色截图）**：

| 场景 | 结果 |
|---|---|
| 进阶详情图片 | `backgroundColor: rgba(0,0,0,0)`、`border-width: 0`；截图确认暗色下无白块 |
| 进阶列表预览 | `rgba(0,0,0,0)`，截图确认卡片里不再有白底 |
| 返回按钮 | 有 `<svg>`，图标右边缘到文字左边缘 **14px**（`gap: 0.5rem`），暗色截图里位置正常 |
| 彩球列表 | 卡片文本 `满力 / 横台一库翻袋 / 酸菜黄花鱼 / 2024-08-31 12:12`，无 `.field`；预览图 `naturalWidth>0`；3 列（280px/列） |
| 彩球详情 | `#/balls/black/07bda534-…`，标题「满力 横台一库翻袋」，meta 黑球/左上袋/作者/时间，三图标签「击球点 / 蓝点 / 路线图」且全部加载成功，四个字段完整；侧栏「黑球」「彩球」高亮 |
| 无图记录 | `mediaCount 0` + 「这条记录没有配图」，不报错（库里有 2 条 `（正在测试）` 空图行） |
| 返回列表 | 筛选条件原样还原：URL `?pocket=top_left&method=横台一库翻袋`、2 张卡、袋口与方式都还在 |
| `typecheck` / `lint` / `build` | 全绿 |

**坑**：

1. **拆详情页后列表的筛选会丢**：`submitted` / `pocket` / `method` 都是组件内 `ref`，从详情页返回时列表**重新挂载**，回到"没查过"的空列表，用户得重查一遍。修法：筛选写进 URL query，列表挂载时读回来；详情页返回用 `router.back()`（`window.history.state.back` 存在时），既带回条件也回到原滚动位置。顺带加了个 `route.query` 监听：点侧栏「黑球」把 query 清掉时，列表同步回到未查询状态，避免"地址栏没条件、列表却有结果"
2. **`el-image-viewer` 只渲染当前一张 `<img>`**（靠 transform 切换），用 `.el-image-viewer__img` 数数量永远是 1，不能拿它判断"一共几张图"
3. **图片底衬别用全局 `--image-frame-bg`**：它是给"小缩略图 + 白底 PNG"设计的，详情页放大后白底会变成一大块白。详情页/列表预览一律透明，空图才用虚线框

## 任务做不完怎么办（很常见）

不要硬做，也不要留半成品。二选一：

1. **回退**：`git checkout -- .`，任务状态改回 `TODO`，在日志写清"为什么没做完"
2. **拆任务**：`T3.2` 拆成 `T3.2a 只做筛选`、`T3.2b 只做卡片`，前者 `DONE`，后者 `TODO`

**绝对不要提交编译不过的代码**——下一个会话会以为它是好的。
