## 2. 国内网络配置（必做，否则装不上 Electron）

Electron 的二进制包默认从 GitHub 下载，国内经常超时。先配镜像：

```bash
npm config set registry https://registry.npmmirror.com
npm config set electron_mirror https://npmmirror.com/mirrors/electron/
npm config set electron_builder_binaries_mirror https://npmmirror.com/mirrors/electron-builder-binaries/
```

或者在项目根目录建 `.npmrc`（**推荐，团队/换机可复现**）：

```ini
registry=https://registry.npmmirror.com
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```



> `.npmrc` 可以入库（不含密钥）。

## 3. 脚手架：注意目录非空的问题

`electron-vite` 的脚手架通常要求目标目录为空或接近为空。而本项目目录里已经有 `docs/`、`AGENTS.md` 等文件。

**推荐做法（最稳）**：

```bash
# 1. 在临时目录生成脚手架
cd E:/Project
npm create @quick-start/electron@latest snooker-scaffold -- --template vue-ts

# 2. 把生成的文件复制进项目目录（不要覆盖已有 docs/）
#    需要复制：package.json, electron.vite.config.ts, tsconfig*.json,
#             src/, resources/, .vscode/, .editorconfig, .eslintrc* / eslint.config.*
#    不要复制：.git/, README.md, .gitignore（项目里已有）

# 3. 删掉临时目录
rm -rf E:/Project/snooker-scaffold

# 4. 装依赖
cd E:/Project/snooker
npm install
```

**备选**：先试 `npm create @quick-start/electron@latest . -- --template vue-ts`，如果脚手架拒绝在非空目录生成，再走上面的方案。

## 5. Supabase 配置（T0.1）

**已接入 Supabase MCP**，绝大部分操作由 AI 直接执行，不需要手动点 Dashboard。

### 5.1 AI 会做的（通过 MCP）

| 操作 | 工具 |
|---|---|
| 建项目 | `create_project`（org `Boom-Projects`，region `ap-southeast-1`） |
| 查状态 | `get_project` |
| 取 URL / key | `get_project_url`、`get_publishable_keys` |
| 建表 / trigger / RLS / RPC | `apply_migration`（拆 4 个 migration） |
| 灌数据 | `execute_sql` |
| 自检 | `list_tables`、`list_migrations`、`get_advisors` |

### 5.2 仍然需要你手动做的两件事

**① 关闭邮箱确认**（没有对应的 MCP 工具）

Dashboard → **Authentication → Providers → Email** → 关掉 `Enable email confirmations`

> 不关的话，注册要发确认邮件，而免费版内置邮件服务**每小时只能发 2 封**，第三个人注册就会 429。

**② 保存数据库密码**

建项目时 AI 会生成一个数据库密码并转给你，**必须立刻存进密码管理器**。这个密码不在任何文件里，丢了只能重置。

### 5.3 关于 key 的两种形态

新项目的 `get_publishable_keys` 可能返回两类：

| 类型 | 格式 | 说明 |
|---|---|---|
| Publishable key | `sb_publishable_...` | **新版推荐**，可独立轮换，新项目优先用这个 |
| Legacy anon key | `eyJhbGciOi...`（JWT） | 兼容用，很多旧代码/文档基于它 |

两者都是**设计上可公开**的，安全性由 RLS 保证。`.env.local` 里统一填 `VITE_SUPABASE_KEY`，值是哪一个都行。

> **`service_role` key 绝对不要出现在客户端，也不要用 `VITE_` 前缀**。它只在服务端脚本里用，且不进 git。

### 5.4 项目建完后的 Dashboard 检查

- **Authentication → URL Configuration**：Site URL 填 `http://localhost:5173`（开发期）
- **Project Settings → General**：确认 region 是 `ap-southeast-1`
- 免费项目 **7 天不活跃会自动暂停**，靠 T0.5 的 cron 保活

## 6. 环境变量

项目根目录建 `.env.local`（**已在 `.gitignore`，不会入库**）：

```ini
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_KEY=sb_publishable_xxxxxxxx
```

同时保留一份 `.env.example`（入库，只有占位符）：

```ini
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_KEY=your-publishable-key
```

> 注意：`VITE_` 前缀的变量会被打进渲染进程产物。**这没问题**——publishable key / anon key 本来就设计成可公开，安全性靠 RLS 兜底。但 `service_role` 绝不能加 `VITE_` 前缀，也绝不能进这个文件。
